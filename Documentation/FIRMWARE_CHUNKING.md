## Chunked SysEx Firmware Send Method

### Status

This document is the design baseline for the next firmware-update commit.

- The current commit may include this document and the refreshed firmware payload generated by the newer hex-to-sysex flow.
- The current product behavior still uses the existing non-chunked firmware send path.
- The chunked send implementation described below is not committed yet and should be treated as planned work.

Implement firmware updating by loading a single `.syx` firmware file, splitting it into complete SysEx packets, and sending those packets sequentially with a device identity/readiness check before every packet.

### Goal

The target product currently does no chunking. The new behavior should avoid sending the entire firmware payload in one write. Instead, it should:

1. Parse the firmware file into complete SysEx messages.
2. Send one SysEx packet at a time.
3. Before each packet, confirm the device is still responsive by sending a firmware identity request and waiting for a reply.
4. Abort if the device stops replying or the firmware file is malformed.
5. After the last packet, wait briefly and perform one final identity check to verify the device came back correctly.

### Input

- A single firmware `.syx` file loaded as raw bytes.
- The file may contain multiple SysEx messages concatenated together.
- Each sendable chunk is one complete SysEx packet.

### SysEx Packet Splitting Rules

Treat the full firmware file as a byte stream.

- A SysEx packet starts at `0xF0`.
- A SysEx packet ends at `0xF7`.
- Every packet sent to the device must be one complete `F0 ... F7` message.

#### Parsing behavior

1. Scan the firmware byte array from start to end.
2. When `0xF0` is found and no packet is currently open, mark the start of a packet.
3. Continue until `0xF7` is found, then slice that full range as one packet.
4. Continue scanning for the next `0xF0`.

#### Validation behavior

- If bytes appear outside any SysEx packet, ignore them but log a warning.
- If another `0xF0` appears before the current packet is closed by `0xF7`, fail with a malformed firmware error for nested SysEx start.
- If the file ends while still inside a packet, fail with a malformed firmware error for unterminated SysEx packet.
- If no complete SysEx packets are found, fail with a malformed firmware error.

### Pre-Chunk Readiness Check

Before sending each packet, verify the device is ready.

#### Required behavior

1. Send a firmware identity request SysEx message.
2. Wait for a firmware/version reply from the device.
3. If a reply is received, proceed with sending the next packet.
4. If no reply is received within the timeout, retry the identity request.
5. If all retries fail, abort the firmware update.

#### Recommended defaults

- `chunkDelayMs`: `100`
- `ackRequestDelayMs`: `10`
- `ackTimeoutMs`: `5000`
- `ackRetryLimit`: `3`

### Chunk Send Loop

For each SysEx packet in order:

1. Run the readiness check.
2. Wait `ackRequestDelayMs`.
3. Send the packet to the MIDI output.
4. Update progress state:
   - `sentChunks`
   - `totalChunks`
   - `sentBytes`
   - `totalBytes`
   - `percent`
   - current `chunkSize`
5. Wait `chunkDelayMs`.
6. Move to the next packet.

### Post-Transfer Verification

After the last chunk is sent:

1. Log that the final firmware packet was sent.
2. Wait `3000 ms`.
3. Send one final firmware identity request.
4. Confirm the device replies in normal firmware mode.
5. Confirm the reported firmware version matches the expected version.

### Failure Conditions

Abort the update if any of the following happen:

- firmware file has nested SysEx starts
- firmware file has an unterminated SysEx packet
- firmware file contains no complete SysEx packets
- device does not reply to the readiness check within retry limits
- MIDI send fails
- final post-transfer identity check does not succeed

### Expected Runtime Logging

A successful run should produce logs shaped like this:

- `starting chunked send ... length=...`
- `requesting firmware identity before chunk firmware payload chunk=N/T attempt=1/3 timeoutMs=5000`
- `sending firmware payload identity request length=6`
- `firmware identity reply before chunk firmware payload chunk=N/T bootloader=true firmware=...`
- `chunk progress firmware payload chunk=N/T chunkBytes=... bytes=... percent=...`
- `chunked send complete firmware payload length=... totalChunks=...`
- `final firmware packet sent, waiting 3000ms before ID request`
- `post-transfer identity check timer fired`
- `sending post-transfer firmware identity request`
- `firmware identity reply bootloader=false firmware=... updating=false`

### Important Design Notes

- Do not chunk by fixed byte count alone.
- Chunk by complete SysEx packet boundaries only.
- One `F0 ... F7` packet equals one sendable chunk.
- The device readiness check must happen before every packet, not just once before the entire transfer.
- Progress reporting should be detailed enough for UI display.
- The final verification request after the full transfer is required.

### Pseudocode

```text
load firmware file as bytes

packets = splitIntoSysExPackets(bytes)

if packets invalid:
  fail

totalBytes = sum(packet.length for packet in packets)
totalChunks = packets.length
sentBytes = 0

for each packetIndex, packet in packets:
  success = false

  for attempt in 1..ackRetryLimit:
    send firmware identity request
    wait for version reply up to ackTimeoutMs

    if reply received:
      success = true
      break

  if not success:
    fail firmware update

  wait ackRequestDelayMs
  send packet
  sentBytes += packet.length
  report progress
  wait chunkDelayMs

wait 3000ms
send final firmware identity request
wait for final reply

if final reply invalid:
  fail

mark firmware update complete
